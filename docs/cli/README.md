## ⌨️ Команды <a name="команды"></a>

| Команда    | Назначение |
|------------|------------|
| `help`     | Справка: список команд, `help <команда>` — по одной |
| `build`    | Объединить Markdown и собрать DOCX (по умолчанию) |
| `merge`    | Только объединить Markdown в bundle |
| `docx`     | Собрать DOCX из готового bundle |
| `pdf`      | Конвертировать DOCX в PDF |
| `validate` | Проверить конфиг и наличие входных файлов |
| `lint`     | Проверить Markdown на ошибки оформления |
| `stats`    | Статистика: главы, рисунки, источники, оценка объёма |
| `preview`  | Сборка одного `.md` в `preview.docx` (без оглавления) |
| `diagnose` | Отчёт о качестве уже собранного DOCX |
| `watch`    | Автопересборка при изменении Markdown, рисунков или листингов (с `--pdf` — и PDF) |
| `doctor`   | Проверка зависимостей Python и движков |
| `init`     | Создать шаблон `config.yaml` |
| `profiles` | Список профилей в конфиге |

Полезные флаги для `build` / `docx` (описание всех можно найти в `help`):

- `--pagination-engine {word,libreoffice}`
- `--pdf` и `--pdf-engine {word,libreoffice}`
- `--profile NAME`
- `--no-preflight`, `--skip-merge`, `--skip-docx`

`stats` выводит число разделов, глав, приложений, рисунков, таблиц, источников,
слов и оценку числа страниц. Пороги `stats.min_sources`, `stats.page_min`,
`stats.page_max` в конфиге дают предупреждения при выходе за рамки.

`preview` собирает одну главу без merge и без оглавления:

```bash
./vkr-builder.sh preview example/md/04-chapter1.md
./vkr-builder.sh preview example/md/04-chapter1.md -o /tmp/ch1.docx
```

`watch` пересобирает при изменениях, прогоняя перед каждой пересборкой тот же
`lint`, что и `build`: ошибка разметки остановит сборку, а не уедет в документ.
С `--pdf` экспортирует и PDF. Пауза после последней правки —
`watch.debounce_ms` в конфиге. Нужен пакет `watchdog` (`pip install watchdog`).

## 🧩 Конфигурация <a name="конфигурация"></a>

`config.yaml` (поверх `config.defaults.yaml`) задаёт профиль и движки. Минимальный
пример:

```yaml
active_profile: example

profiles:
  example:
    docx: example/VKR-example.docx
    markdown_dir: example/md
    images_dir: example/images
    listings_dir: example/listings
    markdown_files:
      - 01-abbreviations.md
      - 02-terms.md
      # ... в порядке документа

build:
  pagination_engine: auto          # auto | word | libreoffice
  libreoffice_path: null
  pdf: false
  pdf_engine: null
  sort_dictionary_lists: false

lint:
  strict: false

stats:
  min_sources: null
  page_min: null
  page_max: null

metadata:
  title: Моя ВКР
  author: Иван Иванов
  created: 2026-01-15
```

Незаданные поля `metadata` очищаются: в документ не попадёт ни имя предыдущего
автора шаблона, ни название программы. Даты принимаются как `2026-01-15` или
`2026-01-15 10:30:00`, кавычки не нужны. Те же значения попадают в PDF.

Оформление задаётся отдельным блоком `style`:

```yaml
style:
  text:
    font_family: Times New Roman
    body_font_pt: 14
  page:
    margins_cm:
      left: 3.0
      right: 1.5
```

Тире приводятся к единому виду блоком `style.dashes`:

```yaml
style:
  dashes:
    normalize: true      # false — оставить ровно то, что набрано в Markdown
    captions: en-dash    # en-dash | em-dash — знак в подписях
    body: en-dash        # en-dash | em-dash — знак препинания в тексте
```

Два случая настройке не подлежат и приводятся всегда:

| Что | К чему | Пример |
|-----|--------|--------|
| тире внутри слова | дефис | `научно–технический` → `научно-технический` |
| тире вплотную между цифрами | среднее тире, тоже вплотную | `2025-2026 гг.` → `2025–2026 гг.` |

Меняется только знак — расстановка пробелов остаётся такой, как набрана.
Поэтому `6 - 7` диапазоном не считается: знак идёт по общему правилу `body`, а
линтер сообщает о находке `spaced-range`.

Настраиваются те два случая, в которых вузы расходятся: подписи и знак
препинания в тексте. По умолчанию везде среднее тире — стандарт ИТМО набран им
и в подписях («Рисунок 1 – Название»), и в связном тексте. Вузу, который
требует длинное, достаточно поставить `em-dash`.

Полный перечень ключей настройки с комментариями — в [`config.defaults.yaml`](../../config.defaults.yaml).

## 🚩 Глобальные флаги <a name="глобальные-флаги"></a>

Применяются ко всем командам:

| Флаг | Назначение |
|------|------------|
| `--config PATH` | Путь к YAML-конфигу (по умолчанию `config.yaml` в каталоге проекта) |
| `--defaults PATH` | Путь к системному конфигу (по умолчанию `config.defaults.yaml`) |
| `--profile NAME` | Профиль из конфига (перекрывает `active_profile`) |
| `-v` / `--verbose` | Подробности по каждому шагу |
| `--debug` | Внутренняя трассировка (Word COM, проходы вёрстки) |
| `-q` / `--quiet` | Только ошибки |
| `--no-color` | Без цвета и перерисовки строки |
| `--ascii` | Только ASCII-символы |
| `--json` | Печатать отчёт одним JSON-документом в stdout |

Пример:

```bash
vkr-builder.bat lint --profile example
vkr-builder.bat build -q --pdf
```

## 🖥️ Вывод команд <a name="вывод-команд"></a>

Все команды печатают отчёт одного вида: заголовок с командой и контекстом, тело с шагами и сообщениями, подвал с результатом и списком созданных файлов.

```text
  vkr-builder.sh build ───────────────────────────  example · word engine

    source     example/md  10 files
    output     example/VKR-example.docx

    ✓ checks       4 checks passed                                    0.0s
    ✓ merge        10 files → _bundle.md                              0.0s
    ✓ lint         no issues                                          0.2s
    ✓ markdown     28 headings, 4 tables, 5 figures, 8 formulas       0.0s
    ▲ 04-chapter1.md:12  unknown reference [рис:k]
    ✓ layout       2 passes, 1 table break                             21s
    ✓ document     example/VKR-example.docx  94 KB                    0.0s

  ✓ build finished in 21s · 1 warning
    document   example/VKR-example.docx   94 KB
```

Идущий шаг остаётся последней строкой со спиннером, на проходах вёрстки под ним рисуется полоса прогресса. Цвет и набор символов можно переключать и переменными окружения — см. ниже.

Про сообщения о проблемах:

- Место указано у каждого сообщения — `файл:строка` в том Markdown, который вы писали.
- Одинаковые сообщения печатаются один раз.
- Предупреждений печатается не больше десяти раз, остальные считаются в подвале; `-v` печатает все. Ошибки печатаются всегда.

Всё показанное выше печатается в **stderr** — чтобы stdout оставался чистым и
его можно было читать программой. В stdout попадает только результат: имена
профилей у `profiles`, текст справки у `help`, пути созданных файлов с `-q`,
весь отчёт одним JSON-документом с `--json`.

```bash
./vkr-builder.sh profiles | grep active
```

### Для скриптов и CI

`-q` печатает только ошибки и абсолютные пути всех созданных файлов в stdout:

```bash
docx=$(./vkr-builder.sh build -q)
```

`--json` заменяет весь отчёт одним JSON-документом в stdout: команда и её
контекст, каждый шаг со своим временем, сообщения с уровнем и местом,
созданные файлы с размерами и итоговый результат. Код возврата не меняется.

```bash
./vkr-builder.sh lint --json | jq '.findings[] | "\(.location) \(.message)"'
```

## 🌍 Переменные окружения <a name="переменные-окружения"></a>

| Переменная | Действие |
|------------|----------|
| `NO_COLOR` | любое значение выключает цвет |
| `FORCE_COLOR` | сохраняет цвет, даже когда вывод перенаправлен |
| `TERM=dumb` | выключает цвет наравне с `NO_COLOR` |
| `VKR_ASCII` | переводит вывод на ASCII-символы, как флаг `--ascii` |
| `VKR_PROJECT_ROOT` | каталог, в котором инструмент ищет `config.yaml` и `config.defaults.yaml` |

`VKR_PROJECT_ROOT` — единственный способ запускать сборку не из каталога
репозитория, не указывая пути к конфигам флагами.

Остальные переменные с префиксом `VKR_` служебные, выставлять их вручную не нужно.

## 🔢 Коды возврата <a name="коды-возврата"></a>

| Код | Когда |
|-----|-------|
| `0` | успех; предупреждения на код не влияют |
| `1` | ошибки линта или сборки, недоступный движок, нечитаемый конфиг |
| `2` | неизвестная команда или неверный флаг |
