# Правила формата Markdown

| en :gb: | ru :ru: |
| ---- | ---- |
| [README.en.md](README.en.md) | README.md |

Компактная спецификация диалекта Markdown, который принимает сборщик. При
генерации текста ВКР следуйте правилам точно. Только Markdown, без HTML —
единственное исключение — директива `@suppress`.

## Нормативная база (ИТМО)

Оформление ориентировано на стандарт ИТМО **ЛНАОБУЧ-СМК-03-05-2022**
(*Требования к выпускным квалификационным работам*, версия 4.0). Один документ,
две ссылки:

- [student.itmo.ru/files/1314](https://student.itmo.ru/files/1314)
- [edu.itmo.ru/files/345](https://edu.itmo.ru/files/345)

Структура разделов и список источников — по ГОСТ 7.32-2017.

## Файлы и порядок

- Несколько `.md` объединяются в порядке `markdown_files` активного профиля в
  `config.yaml`.
- Рекомендуется один логический раздел на файл (сокращения, термины, введение,
  главы, заключение, источники, приложения).
- Блоки разделяются пустой строкой.

## Заголовки

- `#` — уровень 1, `##` — 2, `###` — 3.
- Главы: `# 1 Название`, `## 1.1 Подраздел`. Без точки после номера в `#`.
- Структурные разделы — канонические русские названия ЗАГЛАВНЫМИ, например
  `# ВВЕДЕНИЕ`, `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`, `# ПРИЛОЖЕНИЕ А`.
- Буквы приложений: избегайте **I**, **O** и кириллических **Ё З Й О Ч Ь Ы Ъ**.

## Словарные разделы

Под `# СПИСОК СОКРАЩЕНИЙ И УСЛОВНЫХ ОБОЗНАЧЕНИЙ` или `# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ` —
одна строка на термин:

```text
AST – Abstract Syntax Tree, абстрактное синтаксическое дерево
```

Разделитель термина и определения: ` – ` или ` - ` с пробелами.

## Абзацы

- Обычный текст, между абзацами одна пустая строка.
- Не выделяйте текст жирным ради акцента — при сборке выделение снимается согласно ГОСТ.
- Диапазон чисел и дат набирайте вплотную: `6-7`, `2025-2026 гг.` Знак приведётся
  к среднему тире при сборке, а пробелы вокруг тире останутся как есть — `6 - 7`
  сборка диапазоном не считает и линтер сообщит о находке `spaced-range`.

## Подписи и ключи

Стабильный ключ в фигурных скобках; номер подставляется при сборке:

```text
Рисунок {pipeline} - Подпись
Таблица {req} - Подпись
Листинг {block} - Подпись
```

- Подпись рисунка — **отдельным блоком после** изображения, через пустую
  строку. Без неё картинка и подпись слипаются в один абзац, и рисунок в
  документ не попадёт.
- Подпись таблицы/листинга — **перед** таблицей или блоком кода.
- Разделитель после ключа — дефис или тире; при сборке он приводится к виду
  из `style.dashes.captions` (по умолчанию среднее тире, как в стандарте ИТМО).
- Ключи уникальны в пределах вида объекта: рисунок и таблица могут носить
  одинаковый ключ, два рисунка — нет.

## Рисунки

```markdown
![Схема обработки](fig01-pipeline.png)

Рисунок {pipeline} - Схема обработки

Порядок разбора показан на рисунке [рис:pipeline].
```

Путь — относительно `images_dir` из конфига; имя каталога в нём не
повторяют. Вложенные подкаталоги работают: `diagrams/fig02.png`.

## Формулы

Inline: `\( ... \)`. Display: `\[ ... \]`. Нумерация — ключ на следующей строке:

```text
\[ E = mc^2 \]
{energy}
```

Распознаётся подмножество LaTeX: дроби `\frac{a}{b}`, индексы `x_i` и `x^2`,
операторы `\sum`, `\prod`, `\int` с пределами, греческие буквы, знаки
`\times`, `\cdot`, `\leq`, `\%` и подобные.

## Перекрёстные ссылки

`[prefix:key]` — кликабельная ссылка на номер объекта:

- рисунок: `[рис:pipeline]` (также `pic`, `fig`, `image`)
- таблица: `[табл:req]` (`table`)
- листинг: `[лист:block]` (`listing`, `code`)
- формула: `[форм:count]` (`formula`, `eq`)

Не указывайте номер объекта вручную в ссылках.

## Цитирование

Один стиль на документ.

**Числовой:** `[1]`, `[1; 2]`, `[1-3]`; порядок в списке источников — по первому
упоминанию. `[2024]` без источника остаётся текстом. `[1, 2]` — **не** цитата
(ГОСТ). Экранирование: `\[note\]`, `\{key\}`.

**По ключам** — номера не нужны вовсе. В тексте `[{gost732}]`, несколько
источников через `;`: `[{markdown}; {ecma376}]`. Диапазонов в этой форме нет,
перечисляйте ключи.

Ключ: буквы, цифры, `_`, `-`. Ссылка на ключ, которого нет в списке, — ошибка
(`unknown-citation`); источник, на который никто не сослался, попадает в конец
списка с предупреждением (`uncited-source`).

## Список источников

Заголовок раздела: `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`.

Числовой стиль — одна запись на абзац или пункт списка:

```text
1. Автор А. Заглавие. – М.: Издательство, 2024.
2. Автор Б. Другое заглавие. – 2023.
```

Ключевой стиль — каждая запись начинается со своего ключа и **отделяется пустой строкой**.
Без неё записи слипнутся в один абзац и найдётся только первая:

```markdown
{gost732} ГОСТ 7.32—2017. Отчёт о научно-исследовательской работе. – М.:
Стандартинформ, 2017. – 27 с.

{markdown} Gruber J. Markdown: Syntax [Электронный ресурс]. – URL:
https://daringfireball.net/projects/markdown (дата обращения: 15.03.2026).
```

Список в документе пересобирается по первому упоминанию, поэтому порядок записей
в файле значения не имеет.

## Списки

- Маркированные — строки с `- `.
- Нумерованные — `1)` или `1.` (обе формы печатаются как `1)`).
- Буквенные — `а)` или `a)`.
- Вложенность — отступ два пробела:

```text
- первое направление:
  1) подпункт один;
  2) подпункт два;
- второе направление.
```

## Таблицы

Pipe-формат GitHub; число столбцов в шапке равно числу в каждой строке.
Подпись — перед таблицей:

```markdown
Таблица {metrics} - Показатели производительности

| Показатель | Значение |
|------------|---------:|
| Задержка   | 12 ms    |

Результаты сведены в таблице [табл:metrics].
```

## Листинги

Блок в тройных кавычках, подпись — перед ним:

````markdown
Листинг {api} - Обработчик запроса

```python
def handle():
    return 200
```

Разбор показан в листинге [лист:api].
````

## Листинг из файла

Вместо того чтобы копировать код в Markdown, на него можно сослаться. Строка
`@listing` заменяется содержимым файла:

```text
Листинг {parser} - Разбор блоков Markdown
@listing md.py
```

Путь — относительно `listings_dir` из конфига (если ключ не задан, берётся
`images_dir`). Выйти за пределы этого каталога нельзя.

Фрагмент задаётся номерами строк после двоеточия; правая граница может быть
пустой — тогда до конца файла:

```text
@listing md.py:582-607
@listing md.py:582-
```

Подпись ставится перед `@listing`, как и перед обычным блоком кода. Файл, который
не читается, — ошибка `listing-file`; пустой — предупреждение. Внутри блока кода
`@listing` остаётся текстом.

## Подавление находок

Если находка намеренная — глава цитирует сам синтаксис ссылок, таблица
специально выглядит так, — её можно подавить директивой в HTML-комментарии.
В документ комментарий не попадает.

```markdown
<!-- @suppress -->
Здесь [рис:k] — это пример синтаксиса, а не битая ссылка.
```

| Форма | Действие |
|-------|----------|
| `<!-- @suppress -->` | подавляет всё для следующего элемента |
| `<!-- @suppress имя-правила -->` | подавляет находки этого правила |
| `<!-- @suppress текст -->` | подавляет находки, в тексте которых есть `текст` |
| `<!-- @suppress-file … -->` | то же, но до конца файла |

Директива ставится над элементом — вплотную или через пустую строку, как
удобнее. Несколько директив подряд действуют вместе: так подавляются разные правила
на одном элементе.

Область: директива действует только на свой элемент (или файл) — образец из
главы 1 не заглушит такую же находку в главе 5. Пустой образец подавляет всё, что
относится к элементу.

### Имя правила или текст сообщения

**Пишите имя правила.** Оно не меняется, когда меняется формулировка
сообщения, и все они перечислены в [Правила проверок](../rules/README.md):

```markdown
<!-- @suppress unknown-reference -->
```

Если образец не совпал ни с одним именем правила, он сравнивается с текстом
сообщения — подстрока без учёта регистра. Это удобно для разового случая
(`<!-- @suppress [рис:k] -->` подавит только эту ссылку), но привязывает
документ к сегодняшней формулировке. Имя правила и текст различаются
однозначно, так что обе формы работают одновременно.

Правило каждой находки видно в `--json` (поле `rule`). Полный каталог — [Правила проверок](../rules/README.md).

### Что происходит с подавленными

Оно не исчезает: считается в подвале отчёта (`· 4 suppressed`), остаётся в
`--json` с `"suppressed": true`, а погашенная ошибка не останавливает
сборку — в этом и смысл директивы.

Директива, которая ничего не покрыла, — сама предупреждение: опечатка в имени
правила или уже исправленная находка выглядели бы как действующее оправдание.

```
▲ 04-chapter1.md:12  @suppress caption-ordr matched nothing; did you mean
                     caption-order?
```

## Запрещено

- Жёстко прошивать номера рисунков/таблиц в ссылках.
- Форма цитирования `[1, 2]`.
- Опираться на жирный/курсив для структурирования.
- Смешивать числовой и ключевой стили цитирования в одном документе.
