# Writing thesis Markdown

The full specification is [docs/llm-format/README.md](../../../docs/llm-format/README.md)
(Russian) / [Markdown format rules](../../../docs/llm-format/README.en.md). This is the
working subset: get these right and `lint` stays quiet.

## Where content lives

- One logical section per file under the profile's `markdown_dir`; the order
  is `markdown_files` in `config.yaml`. A new file only takes effect once it
  is listed there.
- `_bundle.md` is generated by `merge` and deleted after the build. Never
  edit it, never commit it, never reference it in an answer — the file the
  author edits is the one named in a finding's location.
- Output Markdown only. No HTML except the `<!-- @suppress -->` directive.

## Headings

```markdown
# 1 Название главы
## 1.1 Подраздел
### 1.1.1 Пункт
```

- No period after the chapter number.
- Structural sections keep their canonical Russian names in caps:
  `# СПИСОК СОКРАЩЕНИЙ И УСЛОВНЫХ ОБОЗНАЧЕНИЙ`, `# ТЕРМИНЫ И ОПРЕДЕЛЕНИЯ`,
  `# ВВЕДЕНИЕ`, `# ЗАКЛЮЧЕНИЕ`, `# СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ`,
  `# ПРИЛОЖЕНИЕ А`.
- Appendix letters skip **I**, **O** and Cyrillic **Ё З Й О Ч Ь Ъ**.
- A heading with no body text under it is a finding (`empty-section`).

## Numbered objects: always a key, never a number

```markdown
![схема](pipeline.png)
Рисунок {pipeline} - Конвейер обработки

Таблица {req} - Требования
| Параметр | Значение |
|---|---|
| A | B |

Листинг {split} - Разбиение блока
```python
def f(): ...
```
```

- Figure caption goes **immediately after** the image, no blank line.
- Table and listing captions go **immediately before** their block.
- Separator after the key is a **spaced** ` - ` or ` – `.
- Keys are short, lowercase, unique per kind.
- Numbering is assigned at build time; inside an appendix it restarts as
  `Б.1`, `Б.2`.
- A listing can come from a real file instead of pasted code — the caption
  stays the same, the fence is replaced by one line:

  ```markdown
  Листинг {split} - Разбиение блока
  @listing md.py:582-607
  ```

  The path is relative to `listings_dir` (or `images_dir` when unset); the
  range is optional and `582-` runs to the end of the file. Prefer this in
  appendices that reproduce source code, so the thesis cannot drift from it.

## References and citations

- Reference by key, never by a literal number:
  `[рис:pipeline]`, `[табл:req]`, `[лист:split]`, `[форм:count]`.
  English synonyms work too (`fig`, `table`, `listing`, `code`, `eq`).
- Citations: `[1]`, `[1; 2]`, `[1-3]` — semicolons between items, hyphen for
  ranges. `[1, 2]` is **not** a citation under GOST and stays plain text.
- Keyed style instead: define `- {gruber} Gruber J. Markdown...` in the
  source list, cite `[{gruber}]`. Do not mix keyed and numeric in one
  document.
- Sources are renumbered by order of first mention, so write them in any
  order and let the tool sort it out.
- Literal brackets in prose must be escaped: `\[note\]`, `\{key\}`.

## Formulas

Inline `\( ... \)`, display `\[ ... \]` as its own block. A number comes from
a key line directly under the formula:

```markdown
\[ N = \sum_{i=1}^{k} 1 \]
{count}
```

## Lists and tables

- `- ` for dashes, `1)` or `1.` for numbers, `а)` for letters; nested items
  indent by two spaces.
- Pipe tables only, and every body row must have exactly as many cells as
  the header (`table-columns` is an error, not a warning).

## When a finding is intentional

Silence it where it happens, by rule name, and leave the rest alone:

```markdown
<!-- @suppress unknown-reference -->
Здесь [рис:k] — пример синтаксиса, а не битая ссылка.
```

`<!-- @suppress-file … -->` covers the rest of the file. Rule names are
listed in the authoring docs; a directive that silences nothing is reported
as a warning of its own, so do not leave stale ones behind.

## Check your work

```bash
vkr-builder.bat lint          # Windows      (./vkr-builder.sh on Linux/macOS)
vkr-builder.bat stats
```

Findings point at `файл:строка` in the source file you edited. Fix them
rather than suppressing them, unless the finding is genuinely intended.
